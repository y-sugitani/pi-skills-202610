# review（レビュー手順）

コードレビュー・差分レビュー・安委譲の成果物回収で使う共通手順。
プロジェクト固有の語彙・表はここに置かず、正本（そのプロジェクトの AGENTS / wiki / プロジェクト skill）を引く。

## レビューするとき

1. 実装方針（プロジェクトの AGENTS.md 等）を先に確認し、差分と突き合わせる
2. 方針からの逸脱は、理由がコード内か journal に記されているかを確認する
3. 似た実装が既存（踏襲元）にないか探し、あれば移植差分だけを見る
4. プロジェクト固有の役割語彙・表・チェック項目はプロジェクト側の正本を参照する
5. 正本が現状に合わない（古い・欠けている）なら指摘する。勝手に直さない

## 安委譲の成果物回収

閉じる判定（末尾・テストの有無）は、この回収ではない。サブの自己申告はそのまま信じない。

1. 完了条件と差分の一覧を突き合わせてから、「レビューするとき」を行う
2. サブの判断が方針（AGENTS / skill）から逸れていたら、コードと正本を引き直す
3. 方針に無い拡張・逸脱は、指示が無い限り差し戻す
4. ユーザーへ完了を言う前に書く: 完了条件と見た差分、自己申告との食い違い、差し戻すか。書かずに完了と言うな

## DRY（まとめるか検討）

似た判断・同じ手順の組み立てが複数箇所に増えたら、まとめるか検討する。
まとめる場合と現状を「見通し / 方針変更の手数 / 片方だけ直して事故る余地」で比べる。

| | まとめる | 現状のまま |
|---|---|---|
| 見通し | 1 箇所で全体が見える | 分割先を渡り歩く |
| 方針変更の手数 | 1 箇所で済む | 複数箇所を直す |
| 片方だけ直して事故る余地 | 無い | 片方だけ直して食い違う |

まとめる方が良いなら、大きな直しをせず短い指導にする（正本に 1 行足し、他は参照にする）。
